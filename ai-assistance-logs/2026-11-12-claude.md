## 1. User request

Today we will be building QDVC Manuscript. QDVC Manuscript is to be a Mac app built with Swift that supports a researcher writing a research article.

USER INTERFACE: QDVC Manuscript has a similar UI to a very simple word processor. The user can type text into the main document-editing window, which should have very comfortable wide margins for easy reading (with three presets). The user can edit body text to be bold, italics, or bold-italics using the usual command-B and command-I shortcuts. Gaps are automatically introduced between paragraphs (no manual empty lines between them). The font should be the lovely serif font from https://github.com/qdvc-apps/qdvc-empirics/

DATA STORAGE: Each manuscript lives in a "workspace" folder which is Git-tracked. If the manuscript does not have sections, it is just manuscript.md. If the manuscript has sections, each section is automatically assigned a name like 01-introduction.md, 02-literature-review.md, etc. Subsections are not given their own files, e.g., 03-research-design.md has all of the section 3 contents including 3.1 Data Collection and 3.2 Data Analysis. If a new section is inserted between 02-literature-review and 03-research-design, then everything is renumbered, that's fine (Git will handle diff-tracking so the provenance of written material is not lost). Each sentence is stored on its own line in the Markdown file, and not automatically reflowed. The manuscript title is stored in YAML frontmatter in a 00-manuscript.md file, as well as any other text that is before the first heading. 

TITLE AND HEADINGS: The user can mark the very first line of the manuscript document as the manuscript title. The user can also mark any line of text as a heading of some level (e.g., Level 1, Level 2, etc.). The user can optionally display heading numbers (e.g., 1. Introduction, 2. Literature Review, 3. Research Design, 3.1 Data Collection, 3.2, Data Analysis, etc.). A navigation outline helps the user jump to a specific section.

DATA VARIABLES: The user can define various data variables and insert them. This is handled in a manner that is compatible with https://github.com/michaelstepner/pandoc-mustache - so yes we can have a YAML file with all the variables.

FIGURES AND TABLES: For now, Figures and Tables are just PNG screenshots. The actual PNG images are stored in the workspace folder. The Figure/Table number and caption is handled by QDVC Manuscript and can be referred to from elsewhere in the manuscript (e.g., "As depicted in `Figure 3`"). If new figures/tables cause renumbering, QDVC Manuscript should handle this.

REFERENCES: QDVC Manuscript can optionally access a QDVC Bibliotheca (https://github.com/qdvc-apps/qdvc-bibliotheca-mac) workspace for easy insertion of in-line citations. Full reference list entries are also managed by QDVC Manuscript, to be inserted in the heading called "References". All in-line citations and reference list entries are stored in the Markdown file as-is (i.e., do not follow a `pandoc-mustache` or `citeproc` kind of logic), and remapped to QDVC Bibliotheca. If you need a supporting file (YAML/CSV) to help with that remapping then we can have that.

MULTI-WINDOW: QDVC Manuscript can pop open multiple windows editing the same file in multiple locations.

FOCUS: The user can toggle any window to "Focus" mode. In focus mode, the current sentence is displayed in regular black text; all other text in the manuscript document fades to light grey text. Toggling focus mode on one window does not impact the others.

TOPIC SENTENCES: A handy feature where the first sentence of every paragraph is emphasised, to see if skimming through the topic sentences is still logically cohert. Two modes: accentuate (use colours and typography to emphasise the topic sentences), collapse (all paragraph contents aside from topic sentences are hidden away, conceptually similar to code-folding in an IDE).

COUNTS: A status bar displays total word count with references, total word count without references, and word count of current sentence.

IMPORT AND EXPORT: Markdown file, DOCX.

OFFLINE ONLY: Please ensure the absolutely no part of this app or is component attempt to access the network or the internet in any way, and that there is no dependency that requires such (e.g., Yams).

### Decisions you may want to change
- **Font:** the serif in QDVC Empirics is New York, the serif built into macOS, so nothing is bundled.
- **Citations** are stored exactly as they read, "(Smith & Jones, 2025)". A `citations.yml` file maps each one to its QDVC Bibliotheca records and keeps a copy of the reference list, so everything still reads correctly when the library isn't connected.
  - **Styles:** APA 7 and ACIS, adapted from Bibliotheca's own formatters, with 2025a/2025b added for works with the same authors and year.
  - **Library location:** chosen per manuscript on each Mac, and only ever read.
- **Cross-references** are also plain text: "Figure 3", "Table 1", "Section 3.2". When a workspace is opened they're recognised again and renumber themselves. A downside is that ordinary prose like "Section 2 of the Act" would be taken as a reference.
- **Figures and the reference list** are each a single object in the text. You can't accidentally type inside them, and renumbering never interferes with Undo. A figure's caption goes below it and a table's caption goes above; double-click to edit the caption.
- **Heading numbers** are drawn in the left margin rather than typed into the text, so they never end up in the Markdown. References, Abstract and Appendix headings are never numbered, and Format › Unnumbered Heading (written as `{-}`) leaves out any other.
- **Collapse mode** is read-only. Double-click a topic sentence to unfold the text and keep editing there.
- **Accentuate mode** can't make topic sentences bolder without changing the text in every window. It uses colour, a highlight, and fading the rest of each paragraph instead.
